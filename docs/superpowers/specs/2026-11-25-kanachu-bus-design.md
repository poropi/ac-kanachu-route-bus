- 日付: 2026-11-25

## 1. ゴールと前提

**神奈中（神奈川中央交通）が使っている一般的な路線バス**（ユーザーの言葉）を Assetto Corsa の車 MOD にする。外観・運転席から見た車内・バスらしい走り・神奈中の塗装をそろえ、ゲームで運転できるようにする。

| 項目 | 決定 | 決めた人 |
|---|---|---|
| 作り方 | A 案: Blender で一から作る。内装（運転席・客席）も作る。物理は諸元から組む | ユーザー |
| 分担 | デザイン関連は Codex の `gpt-6.2-astra` に依頼する（§3） | ユーザー（「デザイン関連」の範囲は私の解釈。§3 で直してほしい） |
| 基準車種 | いすゞ エルガ（LV290 系、短尺の N尺 10.43 m、ノンステップ、前中扉）。メーカーのエンブレムは付けない | 私。理由: 神奈中は 2015 年頃から新車をノンステップ短尺に統一し、近年の新車はエルガが中心（二次資料）。2005 年時点では 9 割以上が三菱車で、全体の最多車種かは統計が無く断定できない |
| 塗装 | 旧塗装（クリーム地に赤・橙の帯）と新塗装（2023 年〜の縦 3 色）の 2 スキン | 私（ユーザーは否定していない） |
| 動作確認 | ゲーム PC（ゲーム PC）の AC で、こちらが起動・自動運転・撮影して確かめる | 私 |
| 用途 | 個人利用。神奈中の名前・塗装・ブランドマークを使うので配布はしない前提 | 私 |

### 目標・目標外・失敗の条件

- **目標**: 神奈中のバスに見える外観（2 塗装）／運転席視点で運転できる／10 t 級の重さとディーゼルの回転域で走る（加速が遅く、回転数が低い）／ゲームのログにエラーが無い。
- **目標外**: Q尺・EV・ハイブリッド・旧型車（エアロスター等）、トルクコンバーター付き AT の厳密な再現、乗客・運賃などのゲーム要素、配布。
- **失敗とみなす**: スポーツカーのように加速する・8,000 rpm まで回る（既存のバス MOD `tky_bus_jetset` はこれ）／ゲームで読めない・止まっていると車体が揺れ続ける／車内視点が無い／写真やロゴ画像をそのまま貼ったテクスチャ。

## 3. 分担と受け渡しの決まり

### 担当

| 担当 | 受け持つもの |
|---|---|
| **Codex `gpt-6.2-astra`**（デザイン） | D1 外装の .blend（車体・窓・扉・灯火・ミラー・ワイパー・行先表示器・バンパー・ホイールとタイヤ）／D2 内装の .blend（運転席・ハンドル・計器盤と針・料金箱・客席・手すり・つり革・降車ボタン・床・天井）／D3 塗装テクスチャ 2 種と、ナンバー・社番・行先表示の絵／D4 UI の絵（badge.png・logo.png・各スキンの livery.png） |
| **Claude 側**（Claude＋Sonnet のサブエージェント） | kn5 書き出し、LOD・当たり判定、物理 ini、CSP 設定、UI の json、組み立て、規約の自動検査、写真との並べ比較、ゲーム PC での試走・撮影 |

- 呼び方: `codex exec -m gpt-6.2-astra --dangerously-bypass-approvals-and-sandbox - < 依頼文.md`（Blender はサンドボックス内で動かないため）。依頼文と受け取った物は `design/requests/NN_*.md`・`design/` に置く。
- 2026-11-25 に `codex exec -m gpt-6.2-astra` が応答することを確認済み（ログの model 行が gpt-6.2-astra）。
- **astra の成果物の確認**（私の提案）: 届いたら Claude 側が規約の自動検査と、写真と同じ向きのレンダーの並べ比較をする。違いは一覧にして astra に直しを頼む。
- **直しが収まらないとき**（私の提案）: 1 部位につき直しの依頼は 3 回まで。3 回で違いが残れば effort を上げて（`-c model_reasoning_effort=xhigh`）もう一度頼み、それでも残れば、残った違いの一覧を添えてユーザーに相談する。**Claude 側が代わりにモデルや絵を作ることはしない**（デザインは astra というユーザーの指示のため）。
- **ユーザーに見せる所**: M2 の終わり（外装の比較画像）と M4 の終わり（塗装 2 種の比較画像）。見せたら止まらずに次へ進む（2026-11-25 ユーザー指示「先進めてください」）。ユーザーから直しの指示が来たらそれを優先する。

### 受け渡しの決まり（astra への依頼文にそのまま入れる）

- **座標**: Blender は Z 上・+Y が車の前・+X が車の右（kn5 では Y 上・+Z 前・+X 左。変換は Claude 側の書き出しで行う）。単位 m。**原点は前後車軸の中点の真下の地面、車幅の中心。**
- **右ハンドル**。運転席は右前。
- **ノード（オブジェクト）名**: `WHEEL_LF`・`WHEEL_RF`・`WHEEL_LR`・`WHEEL_RR`（車輪の中心が原点、回転軸は X。後輪は 2 本のタイヤとホイールを 1 つの WHEEL にまとめ、2 本の中央を後トレッドの位置に置く）、`SUSP_LF`・`SUSP_RF`・`SUSP_LR`・`SUSP_RR`（車軸まわりの部品。無ければ空でよい）、`STEER_HR`（ハンドル。中心が原点、回転軸はハンドル軸）、`COCKPIT_HR`（内装一式の親）、計器の針 `ARROW_SPEED`・`ARROW_RPM`（回転軸が原点）、灯火 `LIGHT_HEAD_L/R`・`LIGHT_TAIL_L/R`・`LIGHT_BRAKE_L/R`・`LIGHT_IND_FL/FR/RL/RR`・`LIGHT_REVERSE_L/R`、行先表示 `DEST_FRONT`・`DEST_SIDE`・`DEST_REAR`、扉 `DOOR_FRONT`・`DOOR_MID`（閉じた状態で作る）。ほかの名前は自由だが、`WHEEL_`・`SUSP_`・`STEER_`・`ARROW_` で始めない。
- **マテリアル名**（書き出しでシェーダに対応させる）: `paint`（塗装。外装の塗装面はすべてこれ 1 つ）、`trim_black`、`chrome`、`glass`（透明）、`glass_light`（灯火のレンズ）、`light_emit`（光る面）、`dest_led`（行先表示）、`tyre`、`rim`、`rubber`、`interior_*`（内装は自由に分けてよい）。
- **塗装の UV**: `paint` の面は 1 枚の UV（0〜1）に全部収め、重ねない。左右側面・前面・後面・屋根を別の島にし、塗装テクスチャ 4096×2048 の上で帯が途切れずに描ける並びにする。UV の配置図（PNG）も一緒に渡す。D3 の塗装テクスチャはこの配置図の上に描く。
- **三角形数**: 外装＋内装で 30 万以下。LOD は Claude 側が削って作る。
- **扉・窓**: ガラスは片面で、内外の両方から見えること（裏向きで消えない）。
- **参照写真は参照だけ。** ロゴ・文字・塗装は描き直し、写真を切り貼りしない。
- 届ける物: `.blend`（パック済みテクスチャ）、UV 配置図、4 方向のレンダー、使った参照写真の URL 一覧。

## 4. 外装

### 寸法の目標（公式諸元。出典は調査資料 §1）

| 項目 | 目標 | 出典 |
|---|---|---|
| 全長 | 10,430 mm | 公式（N5 の表。N3/N4 も同じ N尺と見ている） |
| 全幅 | 2,485 mm（ミラー除く） | 公式 |
| 全高 | 3,105 mm | 公式（N5） |
| ホイールベース | 5,300 mm | 公式 |
| トレッド 前／後 | 2,065 / 1,820 mm | 公式 |
| 最低地上高 | 130 mm | 公式 |
| タイヤ | 275/70R22.5、外径 956 mm（計算）。後輪はダブル | 公式（サイズ）、外径は計算 |
| アプローチ／デパーチャアングル | 9.6° / 8.4° | 公式 |

前後のオーバーハングは公式の旋回軌跡図で前 2,300 mm・後 2,830 mm（2026-11-26 追記）。扉の位置と幅・窓の枚数と位置・床の高さは公式資料に無い。**実車の側面写真から、ホイールベースを物差しにして比率で決める**（astra の作業）。決めた値と使った写真は D1 と一緒に報告してもらう。

### 形の要点（写真で確かめる項目）

前面の大きな 1 枚ガラスと上部の行先表示器、前扉（折戸）と中扉（引戸）、左側面の扉と右側面の窓の並び、屋根の上の冷房装置、後面の機関部の点検ふたと後部の行先表示、ミラー（前に張り出す型）。

### 確かめ方

1. 実車写真と同じ向きでレンダーを撮り、並べ比較の画像を作る（前・横・後・斜め前・斜め後）。
2. 寸法はメッシュから測り、表の値 ±20 mm。
3. 違いは全部直してから次へ進む。比較画像は全部直し終えてから 1 回だけユーザーに見せる。

## 5. 内装

- **運転席**: 座席、ハンドル（大径・寝かせ気味）、計器盤（速度計・回転計の針が動く）、料金箱、運転席まわりの仕切り。運転席の目の位置は実車写真から決める（推定 地上約 2.0 m）。
- **客室**: 79 人仕様の座席 27 席の並び（前向き・横向きは写真に合わせる）、手すり、つり革、降車ボタン、床（ノンステップ部と後部の段差）、天井、窓の内側。
- **ドライバーの人形**: M1 は人形なし（`driver3d.ini` 等を置かない）で、人形が無くても読み込めることを確かめる。M3 で AC の標準の人形（`content/driver`）を、既存の車から借りた座る位置（`driver_base_pos.knh`）とハンドル操作の動き（`steer.ksanim`）で右ハンドル・高い座席に合わせてみる。手がハンドルに合わなければ人形なしで出す。**人形は合格条件に入れない**（運転席視点が成り立てばよい）。

## 7. 音・UI・スキン・CSP

- **音**（2026-11-26 改訂、ユーザー指示）: M1 の試走は、バス MOD `tky_bus_jetset` の音を借りる（個人利用。トラック系 MOD の音は乗用車の音と MD5 一致だったため不採用）。**本番の音は Pixabay の効果音（トラックエンジン）から作る**: AC の音の SDK（ゲーム PC の `sdk\audio\ac_fmod_sdk_1_9`、手順書 `AC Audio Pipeline 1.9.pdf`）のひな形と **FMOD Studio 1.08.12**（手順書が指定する版。fmod.com のダウンロードはログインが要る）で `.bank` を作る。素材は回転が一定の区間を切り出し、音の高さをずらして回転域（600〜2,600 rpm）を作る。Pixabay のライセンスは作品への組み込みを認め、元のままの単体配布を禁じる。
- **UI**（`ui/ui_car.json`）: 名前「Kanachu City Bus (Large Non-step)」、ブランド Kanachu、169 kW・773 N·m・9,790 kg、説明文は日英。トルク・出力の曲線は power.lut から計算する。
- **スキン**（2026-11-26 実装に合わせて改訂）: `skins/0_new2023/`（新塗装、既定）と `skins/1_standard/`（旧塗装）。名前順の先頭が既定になるので、現行の新塗装を先にした（私の判断）。塗装テクスチャはスキンのフォルダに同名で置いて差し替える。各スキンに preview.jpg（Blender のレンダー）・livery.png・ui_skin.json。
- **CSP（`extension/ext_config.ini`）**: ライト・ブレーキ灯・ウインカー・バック灯・行先表示の発光。車内灯は ext_config で点け消しせず、マテリアル（interior_lamp）が常に光る（2026-11-26 実装に合わせて改訂）。

## 8. 完了の判定

### この Mac で確かめる

- 寸法が §4 の目標 ±20 mm（メッシュから実測）。
- 書き出した kn5 を自作の読み込み器で読み戻し、ノード名・マテリアル名・三角形数が意図どおり。
- 写真との並べ比較（5 方向）で、形と塗装の違いを全部直した。

### ゲームで確かめる（ゲーム PC。こちらで実行する）

手順は `hakone_mod_ac/tools/ac/` と同じ（Lua アプリで自動運転・記録・撮影）。AC が使用中でないこと（`acs` が動いていない）を確かめてから始め、`race.ini`・`video.ini` を控えて終わったら戻し、入れた Lua アプリは消す。

使うコース（ゲーム PC に入っていることを 2026-11-25 に確認）:
- `yabitsu` の `s1_up`（秦野の町なかの区間。実際の神奈中の路線の道）: 自動運転の走行と撮影。
- `drift`（Kunos の広い平地）: 旋回半径と横 G。
- `ks_drag` の `drag400`（直線）: 加速と最高速。

1. 車が読み込まれ、AC と CSP のログにこの車のエラーが無い。
2. 止まった状態で 2 秒以内に車体の揺れが収まる。
3. `s1_up` を自動運転で 3 分走って、ひっくり返る・跳ねる・沈み込むことが無い（1 秒ごとの位置と車体の傾きを記録して見る）。
4. `drag400` で: 回転数が 2,600 rpm を超えない。0→40 km/h が 8〜16 秒（仮定の幅。路線バスの発進加速 0.7〜1.4 m/s² 程度と見た値で、実測の資料は無い）。最高速は 115 km/h 以下。
5. `drift` で: ハンドルいっぱいの低速旋回の半径が 8.3 m ±0.5 m（位置の記録から円を当てはめる）。半径 20 m の定常円旋回で、滑り出すかひっくり返る手前の横 G が 0.7 G 以下（後輪を 1 本の広いタイヤにしたことでグリップが出すぎていないかを見る。値は仮定）。
6. 車外（追従・横）と運転席の視点で撮影して、見た目の破綻（穴・ちらつき・裏向きで消える面）が無い。
7. スキン 2 種とライト・ウインカーが切り替わる（M4 以降）。

4・5 の幅を外れたら、ばね・タイヤ・エンジン曲線を直して測り直す。直しは 1 項目につき 3 回までで、それでも外れたら測った値を添えてユーザーに報告する。

## 9. 実車との差として残るもの（2026-11-26 最終確認で更新）

| 項目 | 内容 |
|---|---|
| 音 | Pixabay の効果音（トラック・バスのエンジン）から作った自作の bank。ゲームで読み込めることは確かめたが、**耳での確認はしていない**（ユーザーに聴いてもらう）。4HK1 の実音ではない |
| 変速 | トルコン AT は再現しない。AC の自動変速での近似。AI の自動運転では 2 速の変速のときに 1〜2 サンプルだけ 2,634〜2,655 rpm まで吹ける（drag400 の手動加速では 2,554 rpm） |
| 公式資料が無い寸法 | 前後オーバーハング（2.30／2.83 m）は公式の旋回軌跡図から。扉・窓・床の高さは写真からの推定 |
| 物理の多くの値 | ばね・減衰・重心（高さ 1.1 m）・ブレーキ・空気抵抗・リミッター・駆動損失（0.80）は仮定。0→40 km/h 8.39 s と最高速 101 km/h はこの仮定での計算値で、実測の資料と比べていない |
| 横方向のグリップ | 半径 20 m の定常円の限界は、安全に回れる広さの場所が見つからず測れていない（§8-5 後半）。タイヤの値（DY_REF 0.85）からは 0.75〜0.85 G と見込まれたので、ユーザー判断で横の摩擦を 0.72 に下げた。代わりに drift でハンドルいっぱいの円（重心の半径約 6 m）の速度を上げると、0.30 G の時点で半径が広がって打ち切った（直前に縁石か段差を踏んだ形跡があり、原因は切り分けられていない）。前輪 52° の切れ角での値で、20 m の円の限界ではない |
| 出力の世代差 | N5 の表（169 kW/230 PS）を使う。N3 世代は 177 kW/240 PS の表記がある |
| 後輪 | 見た目はダブル、物理は幅の広いタイヤ 1 本 |
| 運転手 | 神奈中の制服のオリジナルの運転士（MIT）。体は `content/driver/kanachu_driver.kn5`、座らせる位置と腕の動きも自作。ハンドルを ±90° まで回すと、届く間は握ったまま回り、届かなくなった手はリムの上を滑る（持ち替え）。曲がるときに頭を左右に傾ける AC の動き（`[HEAD_MOVEMENT]`）は止め、カーブの方へ少し顔を向ける動きだけ残した（ユーザー判断）。手は指を曲げてリムの上を握る。運転席の視点の目は運転士の頭より約 0.4 m 後ろにあり、頭と首は運転席の視点で隠す。下を向くと上着の背中が写り、ハンドルの中央が隠れる（両手とメーターは見える。README の既知の問題に記載） |
| 尾灯のレンズ | 消えているときに白っぽく見える（実車は赤いレンズ）。点いたときの赤・橙は正しい |
| 行先表示 | 実際の系統（「藤沢駅」など）ではなく「神奈川中央交通」（ユーザー指示） |
| 付けていない物 | メーカーのエンブレム、社番（「ふ43」など）、ナンバーの実番号、IC カード・車いす・注意書きのステッカー |
| 追従カメラ | AC の F1 の追従カメラは全車共通の距離（`system/cfg/chase_cam.ini`）で、全長 10.4 m のバスでは後面のすぐ後ろに来て、画面が「Kanachu」の文字で埋まる（ゲームで確認）。代わりに F6 の車載カメラの 3・4 番を、後ろ上方から見る 2 台（後端から 8 m・13 m）に入れ替えた（AC は F6 を 6 台までしか読まない）。この 2 台はバスの MOD の中にあるので配布だけで効き、ゲームで車体全体と前方の道が見えることを確認した（`circle_drift_20261126_121943`） |
| ログ | `ERROR: GEAR COULD NOT FIND GEAR_1〜6` が出る（運転手と関係なく前から出ている。セットアップの読み込みの段階）。以前の `Variable type cannot be found` は借り物の運転手が原因で、自作に替えて消えた |
| テクスチャ | 塗装のテクスチャが無圧縮（44.7 MB）で、車全体のテクスチャが重い |
